# Getting started

[FlashData](https://flashdata.dev) · [API documentation](https://flashdata.dev/docs)

## Install from source

Use Node.js 22 or newer. In this repository, install dependencies and build:

```sh
npm ci
npm run build
node examples/offline.mjs
```

Create a local npm archive with `npm pack`, then install that file in another application
with `npm install /absolute/path/to/flashdata-dev-sdk-1.0.0.tgz`. No registry release is
required for this workflow. Examples import `@flashdata-dev/sdk`; after a build, that
same package import works from inside this checkout through Node's package self-reference.

## Authenticate

Obtain a key from your [FlashData account](https://flashdata.dev) and pass it as `apiKey`.
Examples read `process.env.FLASHDATA_API_KEY`; a key from your secret manager also works.

```sh
export FLASHDATA_API_KEY="YOUR_API_KEY"
```

```powershell
$env:FLASHDATA_API_KEY = "YOUR_API_KEY"
```

```javascript
import { FlashData } from '@flashdata-dev/sdk';

const client = new FlashData({ apiKey: process.env.FLASHDATA_API_KEY });
const response = await client.google.search({ query: 'coffee', num: 5 });
console.log('Credits:', response.usage.credits);
for (const payload of response.results) {
  for (const hit of payload.organic ?? []) console.log(hit.title, hit.link);
}
```

Keep API-key code on your server. The client rejects browser construction. The SDK
does not load `.env` files; load application configuration before reading `process.env`
if you use them. See [configuration](client.md) for the optional automatic environment lookup.

## Read the response

A realtime response has `source`, `status` (`done`), `created_at`, `usage`, and `results`.
The outer array wraps source-specific payloads, rather than a universal flat hit list.

| Source                                                  | Read from each item of `response.results`                                        |
| ------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Google web / images / news / shopping / videos / places | `organic` / `images` / `news` / `shopping` / `videos` / `places`                 |
| YouTube search and extended search                      | nested `results` list                                                            |
| Metadata                                                | `videoId`, `title`, `duration`, `transcriptLanguages`, optional formats/chapters |
| Transcript / captions                                   | `segments`, `fullText`, `languageCode`, `isAutoGenerated`                        |
| Channel                                                 | channel properties and `videos`                                                  |
| Suggestions                                             | the item is itself a list of strings                                             |
| License check                                           | `videoId`, `permitted` labels                                                    |

Optional upstream fields can be missing or null. Unknown response fields remain available.
Dates and prices retain their upstream representations; the SDK does not guess dates,
currencies or global search ranks. All requests return promises. Use `for await` for
pagination, bulk job listings, and row iteration.

## Choose execution mode

Realtime returns data in the same call. Pass `{mode: 'async'}` as the second source-method
argument to submit background work. Mixed batches create a job for each query; bulk files
apply one source and set of options to many video IDs. Save IDs before waiting and resume
reads with those IDs if your process restarts. Each Google page is a separate paid query.
Use [account discovery](account.md) to check pricing and plan limits before scaling.
